# Run notes

2026-09-24, macOS 14 (Apple silicon), Python 3.12.14 via uv (system python3 is 3.9, below `requires-python`). `sideband scan --timeout 10` exited 134 (SIGABRT) with no output, so no pendant was seen and no address is recorded. The crash report's namespace was TCC: "attempted to access privacy-sensitive data without a usage description ... NSBluetoothAlwaysUsageDescription". The responsible process was the agent host (`claude`), not Terminal. macOS charges Bluetooth access to the app that launched Python, and a host without that Info.plist key gets killed before bleak can raise, so `cli.py`'s `except` never runs. Next step: run the scan from Terminal.app or iTerm, which ask for Bluetooth permission. This will probably matter for the launchd task too, because a bare python under launchd has no app bundle to hold the permission.

2026-09-25, same Mac, real pendant. Wrapping python in an ad-hoc-signed `Sideband.app` whose Info.plist carries `NSBluetoothAlwaysUsageDescription`, launched with `open`, fixed the TCC abort. The launcher script `exec`s python, so the pid (and the grant) stays Sideband's. Scan found `Omi  23602043-C6AF-DD66-2D32-D094F5F87988`. The device reports model "Omi CV 1", manufacturer "Based Hardware", firmware 3.0.19, hardware 5.0, codec 21 (opus-fs320), and a features bitmask of 0x01EC at `19b10021` (button, battery, haptic, offline storage, LED dimming, mic gain; no accelerometer). A 35 s background hold saw no gap. A later 25 s run held 50.3 frames/s, then logged one real `gap 2.0s` and reopened; the timer ended the run before the reopen finished, so that recovery is unconfirmed. Every audio notification carried one 20 ms Opus frame (TOC 0xb8) after the 3-byte header, and 229 frames decoded to 4.58 s of PCM through PyAV. Twice the audio stream showed 0 frames/s while the link stayed up and buttons still worked; cause unknown.

2026-09-25, buttons. `23ba7925` notifies 8-byte little-endian codes from the firmware's own gesture detector (upstream `omi/firmware/omi/src/lib/core/button.c`): 1 single tap about 300 ms after the press, 2 double tap (600 ms window), 5 release. A 3 s hold runs `turnoff_all()` and notifies nothing; the pendant dropped off Bluetooth and stopped advertising when that happened. No triple tap exists.

2026-09-25, firmware. SMP image state over Bluetooth: image 0 slot 0, version 0.0.0, active confirmed bootable. The official `Omi_CV1_OTA_v3.0.21.zip` validates with `imgtool verify` against the public `bootloader/mcuboot/root-rsa-2048.pem` in BasedHardware/omi, so self-built images signed with that key should be accepted. MCUboot is overwrite-only with downgrade prevention: no automatic rollback. Motion is compiled out upstream (`CONFIG_OMI_ENABLE_ACCELEROMETER=n`), and upstream `accel.c` never schedules its first work item, drives a dev-kit pin (gpio1 8) instead of the board's LSM6DS3TR-C regulator (gpio1 12), and sends at 1 Hz. `firmware/accel-stream.patch` fixes those; not built or flashed yet.

2026-09-25, firmware flashed. Toolchain: nrfutil 8.2.1, NCS v2.9.0, upstream BasedHardware/omi 771fe01. A stock build matched the official release (net core same size, app core 128 bytes smaller) and validated against the repo key. Rehearsal: `sideband firmware --update Omi_CV1_OTA_v3.0.21.zip --yes-flash` uploaded both cores over SMP (the first try timed out in service discovery before any upload, fixed with a 30 s connect timeout). The pendant came back in about 10 s with Firmware Revision 3.0.21 and active hash beea5ab7, the official digest. Then the motion build (`firmware/accel-stream.patch`; upstream also never compiled `accel.c`, so the patch adds it to CMakeLists.txt) went on the same way and came back in about 30 s with active hash d0857ecf, features 0x01EE (accelerometer bit set), and service 32403790 / characteristic 32403791 reading 06. Subscribed for 5 s while still: 225 notifications (45/s), all 12 bytes, accel about (-0.24, +0.29, -9.75) m/s², gyro about 0. Tilt steering in Omi Flap 3D not yet tried by hand.

2026-09-25, voice. Omi Voice Flap: pendant Opus → PyAV → 16 kHz PCM → Vosk 0.3.44 with `vosk-model-small-en-us-0.15` and a grammar of go/left/right/up/down/stop/[unk]. Offline check with `say -o … --data-format=LEI16@16000` fed in 20 ms frames at real time: "go left, go up, go right, go down, stop" came out as exactly those five commands in order, each about 0.1–0.2 s after the word, and "hello there, nice weather" produced none. On the pendant a single tap toggled the badge MUTED → LISTENING in the game. Spoken play on the pendant mic not yet reported.
